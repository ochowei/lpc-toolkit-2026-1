# Offline Render Animation Viewer Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make every CLI render publish a portable `<name>.viewer.html` that plays all composed standard and custom animations from the sibling master spritesheet and exposes complete attribution information offline.

**Architecture:** Core adds a pure playback-description helper derived from the existing standard registry and composed custom regions. CLI converts those descriptions plus a portable render summary and complete Credits TXT into one self-contained HTML document, then publishes it through the existing transactional render pipeline and ZIP flow. A deterministic generated fixture lets the existing Web Playwright installation exercise the exact HTML under `file://` without adding a dependency or importing CLI runtime code into Web.

**Tech Stack:** TypeScript 5 strict mode, `@lpc-toolkit/core`, Node.js 22 built-ins, `@napi-rs/canvas`, Vitest, Playwright/Chromium, pnpm 9, RTK.

## Global Constraints

- Add no dependency and no `any` type.
- Keep `packages/core/` environment-agnostic: no React, DOM, browser, Node, Vite, concrete canvas, ZIP, preset, Web, or CLI implementation imports.
- Preserve GPL-3.0-or-later licensing and mandatory metadata plus Credits TXT/CSV artifacts.
- Preserve the existing meanings of `--animation`, `--frames`, `--bundle`, and `--allow-partial`.
- Preserve transactional output: viewer failure must not leave a partial new artifact set.
- The viewer must work through `file://` with no server, `fetch`, CDN, external script, storage dependency, or network access.
- Do not copy absolute artifact paths or local definition roots into viewer HTML.
- Do not modify or initialize `upstream/`.
- Prefix every repository command with `rtk`.
- After each completed task, check its boxes and append implementation notes, the exact verification command with PASS/FAIL, and the full commit hash as required by `AGENTS.md`.

- [ ] **Step 3: Implement the standard descriptor path**

Create `animation-playback.ts` with strict immutable output:

```ts
import { ANIMATION_CONFIGS, FRAME_SIZE } from './constants.js';
import type { AnimationName, ComposedSheet } from './types.js';

export interface AnimationPlaybackDescriptor {
  readonly animation: AnimationName;
  readonly kind: 'standard' | 'custom';
  readonly sourceX: number;
  readonly sourceY: number;
  readonly frameSize: number;
  readonly cycle: readonly number[];
  readonly directions: 1 | 4;
}

export function describeAnimationPlayback(
  sheet: Pick<ComposedSheet, 'animations' | 'customAnimations'>,
): readonly AnimationPlaybackDescriptor[] {
  const descriptors: AnimationPlaybackDescriptor[] = [];
  const seen = new Set<AnimationName>();
  for (const animation of sheet.animations) {
    const config = ANIMATION_CONFIGS[animation];
    if (!config) throw new Error(`Unknown composed animation: ${animation}`);
    if (seen.has(animation)) continue;
    seen.add(animation);
    descriptors.push({
      animation,
      kind: 'standard',
      sourceX: 0,
      sourceY: config.row * FRAME_SIZE,
      frameSize: FRAME_SIZE,
      cycle: [...config.cycle],
      directions: config.num,
    });
  }
  return descriptors;
}
```

- [ ] **Step 3: Implement safe inline-data serialization and static document structure**

Use a JSON serializer that escapes HTML-significant characters and JavaScript line separators:

```ts
function inlineJson(value: unknown): string {
  const escaped: Readonly<Record<string, string>> = {
    '<': '\\u003c', '>': '\\u003e', '&': '\\u0026',
    '\u2028': '\\u2028', '\u2029': '\\u2029',
  };
  return JSON.stringify(value).replace(/[<>&\u2028\u2029]/gu, (character) => escaped[character]!);
}
```
