# CLI 0.1.1 RC Validation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Validate the release candidate for `@lpc-toolkit/cli` version `0.1.1` on macOS and Windows without publishing the package or creating the stable release tag.

**Architecture:** The CLI package version is updated to its stable base version, then committed. The matching annotated RC tag `v0.1.1-rc.1` triggers the existing non-publishing RC workflow. GitHub Actions provides the cross-platform evidence; no `v0.1.1` tag or npm publication is included.

**Tech Stack:** pnpm workspaces, Node.js 22, TypeScript, Vitest, GitHub Actions, Git tags.

## Global Constraints

- Set `packages/cli/package.json` to the stable base version `0.1.1`; do not use an npm prerelease package version.
- Use the exact RC tag `v0.1.1-rc.1` and do not create the stable `v0.1.1` tag.
- Do not publish to npm or change Trusted Publisher configuration.
- Do not modify `upstream/`, add dependencies, or use package managers other than pnpm.
- Run the repository boundary check and the CLI's typecheck, test, build, packed-package smoke, and RC tag verifier before pushing the RC tag.
- Cross-platform RC success requires the tagged `CLI Release Candidate` workflow to pass on both `macos-latest` and `windows-latest`.
